# LDAP Configuration

> **Note:** The ERA automation tool uses an Excel-driven workflow. LDAP configuration
> described below is automatically generated from your Excel template when you run
> `make generate`. You do NOT need to manually edit LDAP settings in YAML files.
> This document is provided as a reference for understanding the LDAP architecture
> and troubleshooting.

**How to enable, disable, and troubleshoot LDAP authentication**

---

## Overview

LDAP (Lightweight Directory Access Protocol) provides **centralized authentication** for:
- **Switches** - Login to switches with LDAP credentials
- **Servers** - Login to compute nodes, storage, support servers

### Benefits of LDAP
- ✅ Centralized user management
- ✅ Single sign-on across infrastructure
- ✅ Easier user provisioning/deprovisioning
- ✅ Audit trail of authentication

### Without LDAP
- Uses local authentication (individual accounts on each device)
- Each switch/server has its own user database
- More manual management

---

## Quick Start

### Enable LDAP

In your Excel template Settings tab, set `ldap_enabled: true` and configure LDAP server IPs. Then:

```bash
make import EXCEL=your-config.xlsx
make generate ARCH=<type>
```

### Disable LDAP

In your Excel template Settings tab, set `ldap_enabled: false`. Then:

```bash
make import EXCEL=your-config.xlsx
make generate ARCH=<type>
```

### Source of Truth

The Excel Settings tab is the source of truth for LDAP configuration. Set `ldap_enabled`
to `Yes` and fill in the LDAP fields. Running `make generate` creates the inventory
with LDAP settings. Do NOT manually edit the generated `group_vars/all/main.yml` --
it will be overwritten on the next `make generate`.

## Configuration Files

### `output/<arch>/<site>/inventory/group_vars/all/main.yml`

Generated by `make generate` from the Excel Settings tab. The LDAP server IPs are used by the switches for authentication.

**With LDAP enabled**:
```yaml
ldap:
  servers:
    - ip: 192.168.200.252
      priority: 1
    - ip: 192.168.210.252
      priority: 2
```

**With LDAP disabled**:
```yaml
ldap:
  servers: []
```

### Manual Configuration (Not Recommended)

> **Warning:** Manual edits to `main.yml` will be overwritten by the next `make generate`.
> Prefer editing the Excel Settings tab and re-running the pipeline.

Edit `output/<arch>/<site>/inventory/group_vars/all/main.yml` directly:

```yaml
ldap:
  servers:
    - ip: 192.168.200.252
      priority: 1
    - ip: 192.168.210.252
      priority: 2
```

Then regenerate configs:

```bash
make generate ARCH=<type>
```

## Deployment Workflows

### Workflow 1: With LDAP

```bash
# 1. Set ldap_enabled: true in Excel Settings tab
# 2. Import and generate
make import EXCEL=your-config.xlsx
make generate ARCH=<type>

# 3. Deploy servers (includes LDAP setup)
make deploy-servers ARCH=<type>

# Result: Centralized authentication!
# Login to any switch/server with: jdoe / Cumu1usLinux!
```

### Workflow 2: Without LDAP

```bash
# 1. Set ldap_enabled: false in Excel Settings tab
# 2. Import and generate
make import EXCEL=your-config.xlsx
make generate ARCH=<type>

# 3. Deploy servers (skips LDAP setup)
make deploy-servers ARCH=<type>

# Result: Local authentication only
# Login to switches with: cumulus / Cumu1usLinux!
```

## When to Enable LDAP

**Enable LDAP if:**
- ✅ You have **multiple administrators** who need access
- ✅ You want **centralized user management**
- ✅ You need **audit trails** of who logged in where
- ✅ You're deploying to **production**
- ✅ You want **consistent credentials** across all devices

**Disable LDAP if:**
- ✅ You're doing **testing/development**
- ✅ You're using **NVIDIA Air** (simpler without LDAP)
- ✅ You're a **single administrator**
- ✅ You want the **simplest possible setup**
- ✅ You're troubleshooting and want **minimal dependencies**

## Testing LDAP

### Verify LDAP Server is Running

On the `dhcp-oob` server:

```bash
# Check LDAP service
sudo systemctl status slapd

# Test LDAP query
ldapsearch -x -b "dc=example,dc=com"
```

### Test LDAP Connection from Switch

```bash
ssh core-01
sudo ldapsearch -H ldap://192.168.200.252 \
  -D "cn=admin,ou=Users,dc=example,dc=com" \
  -w "password" \
  -b "dc=example,dc=com"
```

### Test User Login

```bash
# SSH to a switch
ssh cumulus@core-01

# Try to login with LDAP user
su - jdoe
# Enter password: Cumu1usLinux!

# If successful, you'll see:
# jdoe@core-01:~$
```

### Check Authentication Logs

```bash
# On the switch
sudo tail -f /var/log/auth.log
```

## Troubleshooting

### LDAP Authentication Not Working

**Check LDAP configuration**:
```bash
grep -A5 ldap output/<arch>/<site>/inventory/group_vars/all/main.yml
```

**Check LDAP on switch**:
```bash
nv show system aaa ldap
nv show system aaa authentication-order
```

**Verify LDAP server**:
```bash
# On dhcp-oob:
sudo systemctl status slapd
sudo slapcat  # Dump LDAP database
```

### LDAP Server Unreachable

```bash
# Check network connectivity
ping 192.168.200.252

# Check firewall rules
sudo iptables -L

# Verify LDAP port (389 or 636 for LDAPS)
telnet 192.168.200.252 389
```

### Restart LDAP Service on Switches

```bash
# Via OOB server (Air/Lab)
make restart-ldap ARCH=<type>

# Direct SSH access
make restart-ldap-direct ARCH=<type>
```

### Authentication Fails

```bash
# Check authentication order
nv show system aaa authentication-order

# Check logs
sudo tail -f /var/log/auth.log

# Test with local user first
ssh cumulus@core-01
```

## LDAP Server Setup (If Enabled)

Before enabling LDAP in switch configs, you need:

### 1. LDAP Server Running

```bash
# Check if LDAP server is accessible
ldapsearch -H ldap://192.168.200.252 -x -b "dc=example,dc=com"
```

### 2. Install LDAP Packages on Switches

The ZTP script handles this automatically, but for manual setup:

```bash
# On each switch
sudo apt-get update
sudo apt-get install -y libnss-ldapd libpam-ldapd nscd
```

### 3. Configure LDAP Users

Users in LDAP need proper attributes:
- `uid` - Username
- `uidNumber` - User ID
- `gidNumber` - Group ID
- `homeDirectory` - Home directory path

### Adding More Users

**Option 1**: Edit inventory and reapply
```bash
vim output/<arch>/<site>/inventory/group_vars/all/main.yml

# Add more users to the ldap.users list
make deploy-servers ARCH=<type>
```

**Option 2**: Manually add users via LDAP
```bash
# On dhcp-oob server:
sudo ldapadd -x -D "cn=admin,ou=Users,dc=example,dc=com" -W -f newuser.ldif
```

## Comparison

| Feature | With LDAP | Without LDAP |
|---------|-----------|--------------|
| **Setup Complexity** | Medium | Low |
| **User Management** | Centralized | Per-device |
| **Authentication** | LDAP server | Local accounts |
| **Password Changes** | Once (affects all) | Per-device |
| **Audit Trail** | Yes (LDAP logs) | Per-device logs |
| **Best For** | Production | Testing/Dev |
| **Dependencies** | LDAP server required | None |

---

## Best Practices

1. **Production**: Always enable LDAP
2. **Testing/Dev**: Disable LDAP for simplicity
3. **Security**: Use strong LDAP admin passwords
4. **Backup**: Backup LDAP database regularly: `sudo slapcat > backup.ldif`
5. **Users**: Add real users to LDAP, remove default test users
6. **TLS**: Consider enabling LDAPS (LDAP over TLS) for production
7. **Fallback**: Keep local `cumulus` user as backup authentication
