# NVUE Version Compatibility

## Current Target: Cumulus Linux 5.16+

Templates in this release target **Cumulus Linux 5.15 and later** (tested on 5.16).
NVUE underwent significant structural changes in 5.15. Configs generated by these
templates will **not work** on Cumulus Linux 5.14 and earlier.

## Breaking Changes: 5.14 → 5.15+

Reference: [New and Changed NVUE Commands | Cumulus Linux 5.15](https://docs.nvidia.com/networking-ethernet-software/cumulus-linux-515/Whats-New/New-and-Changed-NVUE-Commands/)

### 1. Feature Toggles: `enable on|off` → `state enabled|disabled`

Nearly every feature enable/disable command changed from `enable on` / `enable off`
to `state enabled` / `state disabled`.

| Old (≤5.14) | New (5.15+) | Templates Affected |
|---|---|---|
| `nv set evpn enable on` | `nv set evpn state enabled` | core |
| `nv set evpn multihoming enable on` | `nv set evpn multihoming state enabled` | core |
| `nv set interface <id> evpn multihoming segment enable on` | `... segment state enabled` | core |
| `nv set interface <id> evpn multihoming uplink on` | `... uplink enabled` | core |
| `nv set interface <id> bond lacp-bypass on` | `... lacp-bypass enabled` | core |
| `nv set nve vxlan enable on` | `nv set nve vxlan state enabled` | core |
| `nv set nve vxlan flooding enable on` | `... flooding state enabled` | core |
| `nv set router bgp enable on` | `nv set router bgp state enabled` | core |
| `nv set router vrr enable on` | `nv set router vrr state enabled` | core |
| `nv set qos roce enable on` | `nv set qos roce state enabled` | core |
| `nv set system telemetry enable on` | `nv set system telemetry state enabled` | core |
| `nv set system wjh enable on` | `nv set system wjh state enabled` | core, oob |
| `nv set vrf <id> evpn enable on` | `... evpn state enabled` | core |
| `nv set vrf <id> router bgp enable on` | `... bgp state enabled` | core |
| `nv set vrf <id> router bgp address-family <af> enable on` | `... <af> state enabled` | core |
| `nv set vrf <id> router bgp address-family ipv4-unicast redistribute connected enable on` | `... redistribute connected state enabled` | core |
| `nv set vrf <id> router bgp address-family ipv4-unicast route-export to-evpn enable on` | `... route-export to-evpn state enabled` | core |
| `nv set vrf <id> router bgp address-family ipv4-unicast route-import from-vrf enable on` | `... route-import from-vrf state enabled` | core |
| `nv set vrf <id> router bgp peer-group <pg> address-family <af> enable on` | `... <af> state enabled` | core |
| `nv set vrf <id> router bgp peer-group <pg> bfd enable on` | `... bfd state enabled` | core |
| `nv set interface <id> qos pfc-watchdog state enable` | Unchanged (`enable`/`disable`, NOT `enabled`/`disabled`) | core |

### 2. IP Namespace Split: `ip` → `ipv4` / `ipv6`

Interface-level IP commands moved under explicit `ipv4` or `ipv6` namespaces.

| Old (≤5.14) | New (5.15+) | Templates Affected |
|---|---|---|
| `nv set interface <id> ip address <prefix>` | `nv set interface <id> ipv4 address <prefix>` | core (lo, SVIs), oob (SVI) |
| `nv set interface <id> ip vrr address <prefix>` | `nv set interface <id> ipv4 vrr address <prefix>` | core |
| `nv set interface <id> ip vrr enable on` | `nv set interface <id> ipv4 vrr state enabled` | core |
| `nv set interface <id> ip vrr state up` | `nv set interface <id> ipv4 vrr vrr-state up` | core |
| `nv set interface <id> ip vrf <name>` | `nv set interface <id> vrf <name>` | core, oob |
| `nv set interface <id> ip gateway <ip>` | `nv set interface <id> ipv4 gateway <ip>` | (not currently used) |

**Exception**: `nv set vrf <id> loopback ip address` stays unchanged — the `ip` → `ipv4`
split only applies to interface-level commands.

### 3. Service Reorganization

| Old (≤5.14) | New (5.15+) | Templates Affected |
|---|---|---|
| `nv set service ntp <vrf> server <server>` | `nv set system ntp server <server>` | core, oob |
| `nv set service lldp` | `nv set system lldp` | (not currently used) |
| `nv set service dhcp-server <vrf>` | `nv set vrf <vrf> dhcp-server-v4` | (not currently used) |
| `nv set service dns <vrf> server` | `nv set system dns server` | (not currently used) |

### 3a. DHCP Relay Restructured (5.14+)

The DHCP relay model changed from `interface`/`server` to `server-group`/`downstream-interface`/`gateway-interface`.

| Old (≤5.14) | New (5.15+) | Templates Affected |
|---|---|---|
| `nv set service dhcp-relay <vrf> interface <iface>` | `nv set service dhcp-relay <vrf> downstream-interface <iface> server-group-name <sg>` | core |
| `nv set service dhcp-relay <vrf> server <ip>` | `nv set service dhcp-relay <vrf> server-group <sg> server <ip>` | core |
| (no equivalent) | `nv set service dhcp-relay <vrf> gateway-interface <iface>` | core |

### 3b. AAA Authentication Order

| Old (≤5.14) | New (5.15+) | Templates Affected |
|---|---|---|
| `nv set system aaa authentication-order 1 local` | `nv set system aaa authentication order local` | core |
| `nv set system aaa authentication-order 2 ldap` | `nv set system aaa authentication order local ldap` (space-separated list) | core |

### 3c. BFD Profile Requirement

In 5.15+, BFD on peer-groups requires a named profile instead of a direct enable/disable toggle.

| Old (≤5.14) | New (5.15+) | Templates Affected |
|---|---|---|
| `nv set vrf <id> router bgp peer-group <pg> bfd enable on` | `nv set router bfd profile default` + `nv set vrf <id> router bgp peer-group <pg> bfd profile default` | core |

A minimal `nv set router bfd profile default` with no parameters uses system defaults (detect-multiplier 3, intervals 300ms).

### 4. Other Changes

| Old (≤5.14) | New (5.15+) | Templates Affected |
|---|---|---|
| `nv set system timezone <tz>` | `nv set system date-time timezone <tz>` | core, oob |
| `nv set system reboot mode cold` | Removed (not supported in VX) | core |
| `nv set interface eth0 ip address dhcp` | Removed (default behavior in VX) | core |

### 5. Unchanged Commands

These commands use the same syntax in both old and new versions:

- `nv set bridge domain ...` (type, vlan, vni)
- `nv set vrf <id> loopback ip address ...`
- `nv set vrf <id> router bgp autonomous-system / router-id / rd`
- `nv set vrf <id> router bgp route-export / route-import`
- `nv set router bgp autonomous-system / router-id`
- `nv set router policy prefix-list / community-list / route-map`
- `nv set nve vxlan source address / decapsulation / encapsulation`
- `nv set nve vxlan flooding head-end-replication`
- `nv set qos traffic-pool ...`
- `nv set interface <id> link state up/down` (admin state, not feature toggle)
- `nv set interface <id> link breakout ...`
- `nv set interface <id> type swp/svi/bond/eth/loopback`
- `nv set interface <id> bridge domain ...`
- `nv set interface <id> bond member ...`
- `nv set interface <id> evpn multihoming segment local-id / mac-address`
- `nv set interface <id> telemetry histogram ...`
- `nv set system hostname / message / api state / config auto-save state / ssh-server state`
